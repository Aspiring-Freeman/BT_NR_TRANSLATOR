# UTF-8 字符导致 printf 格式化错误问题

**日期**: 2025-12-31
**状态**: 已解决
**影响**: MES 开始测试配置显示错误

---

## 问题描述

在嵌入式系统（FM33LG0xx MCU）中使用 EasyLogger 的 `log_i` 宏打印包含 UTF-8 多字节字符的格式字符串时，后续参数值显示错误。

### 症状

```c
// 原始数据
raw[3] = 0x00  // station_id 应该是 0
raw[4..9] = 05 02 50 00 00 77  // meter_number 应该是 "050250000077"

// 错误显示
log_i("║ 工位号: %d", raw[3]);        // 显示 13，应该是 0
log_i("║ 表  号: %s", meter_str);     // 显示 "0A0250000077"，应该是 "050250000077"

// 正确显示（同样的数据）
log_d("station_id=%d", raw[3]);       // 正确显示 0
log_d("表号=%s", meter_str);          // 正确显示 "050250000077"
```

### 关键观察

| 格式字符串类型 | 显示结果 |
|---------------|---------|
| 纯 ASCII + 中文 | ✅ 正确 |
| 包含 Unicode Box Drawing (╔║╗╚╝═) | ❌ 错误 |
| 包含 Emoji (✅❌🔧) | ❌ 错误 |

---

## 根因分析

### UTF-8 编码特性

UTF-8 是变长编码：
- ASCII 字符: 1 字节 (`0x00-0x7F`)
- 中文字符: 3 字节 (`0xE0-0xEF` 开头)
- Box Drawing 字符: 3 字节 (`║` = `0xE2 0x95 0x91`)
- Emoji: 4 字节 (`✅` = `0xE2 0x9C 0x85`)

### 问题原因

嵌入式系统的 `printf` 实现（通常是精简版）在解析格式字符串时：

1. **逐字节扫描** 格式字符串查找 `%` 符号
2. UTF-8 多字节字符中可能包含与 `%` 或格式说明符相似的字节值
3. 导致 **参数栈偏移错误**，读取了错误位置的参数

### 示例

```
"║ 工位号: %d"
 ↓
E2 95 91 20 E5 B7 A5 E4 BD 8D E5 8F B7 3A 20 25 64
         ^^ 空格                              ^^ %d

某些精简 printf 实现可能误解析 E2/95/91 等字节
```

---

## 解决方案

### 方法：使用 ASCII 字符替代 Unicode

**修改前**（有问题）：
```c
log_i("╔══════════════════════════════════════════════════════╗");
log_i("║ 工位号: %d", station_id);
log_i("║ 表  号: %s", meter_number);
log_i("╚══════════════════════════════════════════════════════╝");
```

**修改后**（正常工作）：
```c
log_i("+======================================================+");
log_i("| 工位号: %d", station_id);
log_i("| 表  号: %s", meter_number);
log_i("+======================================================+");
```

### ASCII 替代对照表

| Unicode 字符 | ASCII 替代 | 说明 |
|-------------|-----------|------|
| `╔` `╗` `╚` `╝` | `+` | 角落 |
| `║` | `\|` | 垂直线 |
| `═` | `=` | 双横线 |
| `─` | `-` | 单横线 |
| `╠` `╣` | `+` | T 型连接 |
| `✅` | `[Y]` | 勾选 |
| `❌` | `[N]` | 未选 |
| `🔧` | `[*]` | 工具图标 |

## 注意事项

### 1. 嵌入式系统 printf 限制

- 不要在格式字符串中使用 Unicode Box Drawing 字符
- 不要在格式字符串中使用 Emoji
- 中文字符通常安全（因为不包含与格式符冲突的字节）

### 2. 安全的做法

```c
// ✅ 安全：纯 ASCII 边框 + 中文内容
log_i("+------------------------+");
log_i("| 测试配置               |");
log_i("+------------------------+");

// ✅ 安全：无边框，纯文本
log_i("工位号: %d", station_id);

// ❌ 危险：Unicode 边框字符
log_i("║ 工位号: %d", station_id);
```

### 3. 调试技巧

如果怀疑 printf 格式问题：
1. 使用 `log_d` 打印原始值验证数据正确性
2. 对比有/无 Unicode 字符的输出
3. 检查参数是否"偏移"（显示了相邻参数的值）
