§ 01

Architecture / 内部架构

SIGNAL CHAIN

理解一颗芯片的最佳起点是它的内部信号链。INA219 把"差分输入电压"经过模拟前端处理后转为数字码值，再通过硬件运算得到电流和功率——这条链路上的每一段都对应了你将要配置的寄存器位。

Vs │ (Supply) ┌──────────────────────┼─────────────────────────────┐ │ ▼ │ VIN+ ──○─┐ ┌─ × ───→ POWER REG (0x03) VIN- ──○─┤── PGA ──→ ADC ──→ MUX ──┼─ ──→ CURRENT REG (0x04) │ │ ┌→ SHUNT V REG (0x01) │ └───┤ │ [/1] ±40mV ┌→ BUS V REG (0x02) │ [/2] ±80mV ←── Bus V tap ──→ │ [/4] ±160mV CONFIG REG (0x00) │ [/8] ±320mV CALIB REG (0x05) GND │ ──○──────────────────────────────┼──→ I²C / SMBus ──→ MCU │ (SDA, SCL, A0, A1) ┴ ANALOG DOMAIN ─────────────────┴── DIGITAL DOMAIN

关键节点

整条信号链可以划分成三个域：

  • 差分输入级：VIN+/VIN- 接到 Rshunt 两端，PGA 测量它们的差分电压（即 Rshunt 上的压降），共模电压可达 26V，这就是"高边检测"的基础。
  • 模数转换：12 位 ADC 是模拟域和数字域的边界。它的精度决定了所有派生指标的精度上限。
  • 数字运算：硬件乘法器根据 Calibration 寄存器把"分流电压码值"换算成电流码值，再乘以总线电压得到功率码值——这一步让 MCU 不用做浮点运算。
关键认知
Calibration 寄存器不"校准芯片误差"。它的真实作用是把外部 Rshunt 的阻值信息告诉芯片，让硬件运算单元能正确换算电流。这是 INA219 上手最容易踩坑的概念，详见 §05。

§ 04

PGA & 分流电压量程

GAIN STAGE

PGA 决定了 INA219 能接受的最大分流电压，并不直接决定分辨率——分辨率是固定的 10 µV/LSB。改变 PGA 档位实际上是在改变"满量程对应的码值范围"。

PGA 配置位 12:11满量程 Vshunt满量程电流
（Rshunt=0.1Ω）		满量程电流
（Rshunt=0.01Ω）		1 LSB
/100±40 mV±400 mA±4 A10 µV
/201±80 mV±800 mA±8 A10 µV
/410±160 mV±1.6 A±16 A10 µV
/811 (默认)±320 mV±3.2 A±32 A10 µV
为什么 LSB 总是 10 µV
寄存器是 16 位（15 数据 + 1 符号）。在 PGA=/8（最大档）下需要表达 ±320 mV，所以最大数据值是 32000，对应 1 LSB = 320 mV / 32000 = 10 µV。其他 PGA 档下 ADC 实际只用到一部分位，但 LSB 单位对软件层始终一致——这是 TI 故意设计的，方便驱动代码不用根据 PGA 档切换换算系数。

PGA 选型策略

  1. 根据负载最大电流和 Rshunt 算出最大分流压降：Vmax = Imax × Rshunt
  2. 选择刚好覆盖 Vmax × 1.25（留 25% 余量）的 PGA 档位
  3. 不要无脑选 /8——量程越大，相对噪声越大，相对精度越低
§ 05

Calibration 公式推导

FIRST PRINCIPLES

手册上那个 0.04096 不是魔术数字。它是从芯片内部硬件运算流程一步步推出来的——理解了来历，公式就再也不会用错。

第一步：芯片内部的硬件运算

Current 寄存器的值不是 ADC 直接输出的，而是芯片内部的硬件乘法器算出来的：

Current_Reg =
ShuntVoltage_Reg × CAL
4096

右移 12 位（即除以 4096）是芯片内部固定的位宽对齐操作，写在硅片里改不了。

第二步：从物理量倒推

我们想要的关系是：寄存器值乘以 Current_LSB 等于真实电流。

ShuntVoltage_Reg × 10 µV

0.04096 的真正来历
0.04096 = 4096 × 10 µV = 4096 × 10⁻⁵ V。它把芯片内部的"右移因子 4096"和"分流电压 LSB = 10 µV"两个常数合并到了一起。这不是 TI 凭空凑出来的，而是物理推导的必然结果。

Current_LSB 怎么选

Current_LSB 是你自己选的，它决定了电流测量的分辨率和量程权衡。

经验公式（最大化动态范围）：

Current_LSBmin =
Imax,expected
2¹⁵
=
Imax,expected
32768

但实际工程中我们不取这个理论最小值，而是四舍五入到一个软件好算的整数，比如 1 µA、10 µA、50 µA、100 µA。这样固件里的换算简化为整数乘法。

Power_LSB 是 Current_LSB 的固定倍数

Power 寄存器的换算系数不需要你单独算，芯片内部固定为 Current_LSB 的 20 倍：

Power_LSB = 20 × Current_LSB

这个 20 倍不是任意选的，而是基于"总线电压 LSB = 4 mV"和"内部右移 5000"的硬件约束推出的。在这里我们只需要记住：Power 的物理单位 = 寄存器值 × 20 × Current_LSB。

完整驱动代码（基于现有项目风格）

  FIRMWARE




下面这套代码采用软件 I²C + 通道切换的架构，对应你板子上"两路 INA219 + 旁路 PMOS"的硬件设计。关键改进点：



    
  
  • Calibration 计算用宏自动化，避免手算导致的常数错误（§09 复盘案例的根因）
    • 
  
  • 编译期断言校验 Rshunt × Current_LSB × CAL 三者一致
    • 
  
  • Current_LSB 以 µA 为单位，固件直接用整数运算，无需浮点

头文件 ina219.h（核心配置）



/**
 * @file  ina219.h
 * @brief INA219 高边电流检测驱动 — 核心配置与接口
 *
 * 设计要点：
 *   1. Calibration 由 R_SHUNT 和 CURRENT_LSB 自动算出，避免手算错误
 *   2. Current_LSB 单位为 µA/bit，固件层使用整数运算
 *   3. 提供编译期断言确保配置自洽
 */
#ifndef INA219_H
#define INA219_H

#include "fm33lg0xx_fl.h"
#include "board_pins.h"

/* ===== 硬件参数（根据板子改这里） ===== */
#define INA219_R_SHUNT_OHM       0.1f      /* 分流电阻阻值 (Ω) */
#define INA219_CURRENT_LSB_uA    100       /* 电流分辨率 (µA/bit), 整数 */
#define INA219_MAX_CURRENT_A     2.0f      /* 期望最大电流 (A), 用于校验 */

/* ===== Calibration 自动计算（不要手改） =====
 * 公式: CAL = 0.04096 / (Current_LSB × R_shunt)
 *      = 40960 / (CURRENT_LSB_uA × R_SHUNT_mΩ)
 *
 * 编译期常量, 编译器会折叠成立即数, 不占运行时
 */
#define INA219_CAL_VAL  ((uint16_t)(40960.0f / \
    ((float)INA219_CURRENT_LSB_uA * INA219_R_SHUNT_OHM * 1000.0f) + 0.5f))

/* Power_LSB 固定为 20 × Current_LSB */
#define INA219_POWER_LSB_uW   (20U * INA219_CURRENT_LSB_uA)

/* ===== 编译期自检 =====
 * 防止后人改了 R_SHUNT 但忘了同步 CAL 的批量错误
 */
_Static_assert(INA219_CAL_VAL > 0 && INA219_CAL_VAL <= 0xFFFE,
    "INA219: CAL out of range. Check R_SHUNT and CURRENT_LSB_uA");

_Static_assert((INA219_MAX_CURRENT_A * INA219_R_SHUNT_OHM) <= 0.32f,
    "INA219: max V_shunt exceeds PGA=/8 range (320mV). Reduce R_SHUNT.");

/* ===== I²C 地址（A1=A0=GND 时为 0x40） ===== */
#define INA219_I2C_ADDR_7BIT     0x40
#define INA219_I2C_ADDR_WRITE    (INA219_I2C_ADDR_7BIT << 1)
#define INA219_I2C_ADDR_READ     ((INA219_I2C_ADDR_7BIT << 1) | 0x01)

/* ===== 寄存器地址 ===== */
#define INA219_REG_CONFIG        0x00
#define INA219_REG_SHUNT_V       0x01
#define INA219_REG_BUS_V         0x02
#define INA219_REG_POWER         0x03
#define INA219_REG_CURRENT       0x04
#define INA219_REG_CALIBRATION   0x05

/* ===== 配置寄存器值（详见 §03） =====
 * BRNG=0 (16V), PGA=/2 (±80mV), BADC=12-bit, SADC=12-bit×128avg, MODE=连续 */
#define INA219_CONFIG_VALUE      0x1FE7

/* ===== 通道枚举 ===== */
typedef enum {
    INA219_CH_MAIN = 0,
    INA219_CH_NB = 1,
    INA219_CH_NUM
} ina219_channel_t;

/* ===== 对外接口 ===== */
void     ina219_init(void);
int32_t  ina219_read_current_uA(ina219_channel_t ch);
int32_t  ina219_read_bus_mV(ina219_channel_t ch);
int32_t  ina219_read_power_uW(ina219_channel_t ch);
int32_t  ina219_read_shunt_uV(ina219_channel_t ch);

void     ina219_measure_enable(ina219_channel_t ch);
void     ina219_measure_disable(ina219_channel_t ch);

#endif /* INA219_H */



初始化与读取（ina219.c 节选）



/**
 * @brief 写 INA219 配置寄存器和校准寄存器
 *
 * 必须在使用 Current/Power 寄存器之前调用，否则读出来全是 0。
 * 这是 INA219 最经典的踩坑点。
 */
static uint8_t ina219_chip_init(ina219_channel_t ch)
{
    uint8_t rc;
    ina219_channel = ch;

    /* 1. 写配置寄存器 (PGA, ADC 模式等) */
    rc = ina219_write_reg(INA219_REG_CONFIG,
            (INA219_CONFIG_VALUE >> 8) & 0xFF,
             INA219_CONFIG_VALUE       & 0xFF);
    if (rc) return rc;

    /* 2. 写校准寄存器 (告诉芯片 Rshunt 是多少) */
    rc = ina219_write_reg(INA219_REG_CALIBRATION,
            (INA219_CAL_VAL >> 8) & 0xFF,
             INA219_CAL_VAL       & 0xFF);
    return rc;
}

/**
 * @brief 读取电流值（已转换为 µA）
 * @return 电流 (µA)，正值=正方向，负值=反向。INT32_MIN 表示通讯失败。
 */
int32_t ina219_read_current_uA(ina219_channel_t ch)
{
    uint16_t raw;
    if (ina219_read_reg16(ch, INA219_REG_CURRENT, &raw) != 0) {
        return INT32_MIN;
    }
    /* 寄存器是 16 位有符号二补码 */
    int16_t signed_raw = (int16_t)raw;
    return (int32_t)signed_raw * INA219_CURRENT_LSB_uA;
}

/**
 * @brief 读取功率值（已转换为 µW）
 */
int32_t ina219_read_power_uW(ina219_channel_t ch)
{
    uint16_t raw;
    if (ina219_read_reg16(ch, INA219_REG_POWER, &raw) != 0) {
        return INT32_MIN;
    }
    /* Power 寄存器无符号 */
    return (int32_t)raw * (int32_t)INA219_POWER_LSB_uW;
}

/**
 * @brief 读取总线电压（已转换为 mV）
 */
int32_t ina219_read_bus_mV(ina219_channel_t ch)
{
    uint16_t raw;
    if (ina219_read_reg16(ch, INA219_REG_BUS_V, &raw) != 0) {
        return INT32_MIN;
    }
    /* Bus Voltage 低 3 位是状态位 (CNVR/OVF/保留)，需右移 */
    uint16_t data = raw >> 3;
    return (int32_t)data * 4;  /* LSB = 4 mV */
}

/**
 * @brief 读取分流电压（已转换为 µV，用于调试）
 */
int32_t ina219_read_shunt_uV(ina219_channel_t ch)
{
    uint16_t raw;
    if (ina219_read_reg16(ch, INA219_REG_SHUNT_V, &raw) != 0) {
        return INT32_MIN;
    }
    return (int32_t)(int16_t)raw * 10;  /* LSB = 10 µV */
}




  
为什么这套代码不会出 §09 的错

  关键差异在 INA219_CAL_VAL 是编译期由 R_SHUNT 和 CURRENT_LSB_uA 自动算出的，不是手算后写死的常数。任何人改了 R_SHUNT，CAL 立即同步更新，不会出现注释和实际值脱节的情况。再加上 _Static_assert 校验，编译就会拦下不合法配置。











  § 09
  
现场复盘：836 µA 异常读数

  CASE STUDY




这是一次真实的生产固件案例。无负载状态下 INA219 稳定读到 836 µA，且非常稳定（±2 µA）。表面看像是真实的"待机功耗"，深挖下来才发现 Calibration 寄存器值算错了 62.5 倍。



现象

排查过程



步骤 1：判定噪声 vs 偏移


读数标准差只有 1 µA，远小于均值 836 µA——这是系统性偏移而非随机噪声。如果是噪声，跨度会大得多，偶尔还会出负值。



步骤 2：核查代码中的 Calibration 注释


翻代码发现一段可疑的注释：

// CAL = 0.04096 / (0.000001 * 100) = 409600 = 0x6400
//                                    ^^^^^^   ^^^^
//                                    错算结果 错的转换
#define INA219_CAL_VAL_HI 0x64
#define INA219_CAL_VAL_LO 0x00

根因分析




  
两个独立错误叠加

  错误 #1：原作者算 CAL 时小数点错位，把 409.6 写成 409600。

  错误 #2：把 409600 转十六进制时又错成 0x6400（应该是 0x64000，且超出 16 位寄存器范围）。

  两个错误叠加后，写入的 CAL = 25600，恰好是正确值 410 的 62.5 倍。读数被同步放大 62.5 倍，但看起来还像合理数字，所以多年没人发现。




修复



/* 错误版本 */
// CAL = 0.04096 / (0.000001 * 100) = 409600 = 0x6400  // ✗ 错
#define INA219_CAL_VAL_HI 0x64
#define INA219_CAL_VAL_LO 0x00

/* 正确版本：用宏自动计算，避免手算 */
#define R_SHUNT_OHM      100.0f
#define CURRENT_LSB_uA   1
#define INA219_CAL_VAL   ((uint16_t)(40960.0f / \
    ((float)CURRENT_LSB_uA * R_SHUNT_OHM * 1000.0f) + 0.5f))
/* 编译时自动算出 INA219_CAL_VAL = 410 = 0x019A */

/* 编译期断言：防止以后改错 */
_Static_assert(INA219_CAL_VAL == 410, "CAL mismatch");



更深层的问题：100Ω 这个 Rshunt 选错了



修复 CAL 后，读数会回到约 13 µA 的真实漏电流。但这个板子有更深层的问题：100Ω 的分流电阻只适合测 µA 级超低电流。

你这块板子要测的电流范围跨越多个数量级（µA 休眠 → 100+ mA 发射），单一 Rshunt 根本覆盖不了。建议方案：



    
  
  • 方案 A：板子上两路 INA219 分别用不同 Rshunt，一路 100Ω 测休眠，另一路 0.1Ω 测发射
    • 
  
  • 方案 B：升级到 INA228（20-bit ADC，120 dB 动态范围），单一 Rshunt 即可覆盖 µA ~ A
    •

现场故障诊断速查

  EXPAND TO READ




下面是 INA219 调试时最常遇到的几类异常现象。点击展开查看排查思路。




  

    
Current/Power 读数恒为 0 SEV.HIGH

    

      
最可能原因

      
忘了写 Calibration 寄存器（0x05）。这是 INA219 最经典的坑。Current 和 Power 寄存器都依赖 CAL 才能产生有效值。

      
验证方法

      
读 Shunt Voltage 寄存器（0x01）。如果 ShuntV 有正常读数，说明 ADC 工作正常，问题就是 CAL 没写。

      
修复

      
初始化时按顺序写：先 Config（0x00），再 Calibration（0x05），缺一不可。

    

  


  

    
读数稳定但不准（系统性偏移） SEV.HIGH

    

      
典型表现

      
读数极稳定（标准差 < 均值的 1%），但和万用表对比偏差固定倍数（比如 62.5 倍、10 倍、100 倍）。

      
最可能原因

      
Calibration 值算错了。偏差倍数往往就是 CAL_actual / CAL_correct 的比值。常见错误：单位混淆（µA vs A）、小数点错位、十进制/十六进制转换错误。

      
验证方法

      
用 §06 计算器重算 CAL，对比代码中的常数。如果不一致，问题就在这里。

      
修复

      
用宏自动算 CAL（见 §08），不要手写常数。加 _Static_assert 防回归。

    

  


  

    
读数饱和或溢出 SEV.MED

    

      
典型表现

      
电流大了之后读数卡在某个最大值不变，或 Bus Voltage 寄存器的 OVF 标志位（bit0）置 1。

      
最可能原因

      
PGA 量程选小了。最大分流压降（Imax × Rshunt）超过了 PGA 满量程。

      
修复

      
提高 PGA 档位（/1 → /2 → /4 → /8），或减小 Rshunt。用 §06 计算器自动推荐合适的 PGA。

    

  


  

    
无负载时仍读到几十~几百 µA SEV.LOW

    

      
常见原因（按优先级）

      
1. PMOS 旁路漏电流。很多设计在 INA219 旁边并联 PMOS 实现"旁路+测量"切换。PMOS 截止时仍有 IDSS（典型 µA 级，温度高时变大）。

      
2. INA219 自身失调电压。典型 ±10 µV / 最大 ±100 µV。Rshunt=0.1Ω 时对应 ±100 µA 误差，Rshunt=1Ω 时对应 ±100 µA → ±10 µA。

      
3. 寄生路径漏电流。PCB 受潮、助焊剂残留、多电源域间漏电。

      
解决思路

      
软件做零点补偿（开机时短路输入测一次零点）；硬件检查 PMOS 驱动电平是否到位。

    

  


  

    
I²C 通讯失败（NACK） SEV.HIGH

    

      
检查清单

      
1. 7-bit 地址错。INA219 默认地址 = 0x40 + (A1×4) + A0×1。请确认 A0/A1 引脚电平。

      
2. 上拉电阻问题。I²C 需要外部上拉，4.7kΩ 是常见值。如果用了 10kΩ 但总线电容大（多从机），可能时序不达标。

      
3. SDA 卡死。从机在传输中途被复位会把 SDA 钉低。需要 9 个时钟脉冲做"总线恢复"。

      
4. 时序违规。软件 I²C 的延时是否够。INA219 最高支持 2.94 MHz，但实际板上 100~400 kHz 更稳。

    

  


  

    
读数随负载变化但比例不对 SEV.HIGH

    

      
最可能原因

      
Rshunt 的实际值和代码中假设的不一致。可能是：

      
    
        
  • BOM 误用了不同阻值的电阻（5% 厚膜电阻可能和精密电阻外观一样）
    • 
        
  • Rshunt 焊接不良，引入接触电阻
    • 
        
  • PCB 走线没用 Kelvin 连接，大电流走线的铜阻被算到了 Rshunt 上
    • 
      

      
验证方法

      
万用表四线测量 Rshunt 的实际阻值（去焊一颗或用 Kelvin 探针）。

    

  


  

    
读数温度漂移大 SEV.MED

    

      
主要漂移源

      
1. Rshunt 温度系数。普通厚膜电阻 ±100 ppm/°C，温度变化 50°C 就是 0.5% 误差。精密电流采样电阻（康铜/锰铜）只有 25~50 ppm/°C。

      
2. INA219 自身温漂。失调温漂 0.1 µV/°C，在 Rshunt=0.01Ω 时对应 10 µA/°C 的漂移。

      
3. Rshunt 自发热。大电流下电阻自身发热，阻值变化。

      
解决思路

      
用专用电流采样电阻；Rshunt 选合适功率封装（避免自发热）；高精度场合考虑 INA226（自动零漂消除）。

    

  


  

    
Bus Voltage 数值异常（除以 8 才对） SEV.LOW

    

      
原因

      
Bus Voltage 寄存器（0x02）的低 3 位是状态位（CNVR=bit1, OVF=bit0, 保留=bit2），不是数据。读出来的 16 位需要右移 3 位才能得到电压数据。

      
修复

      
uint16_t raw = read_reg(BUS_V);
uint16_t data = raw >> 3;       // 关键!
int32_t mV = data * 4;          // LSB = 4 mV
